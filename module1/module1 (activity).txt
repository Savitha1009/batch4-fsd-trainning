ACTIVITY 1: BROWSER–SERVER–DATABASE INTERACTION
============================================================

Title:
Students simulate the interaction between a browser, server, and database to understand how requests are processed and responses are returned.

Introduction:
The Browser–Server–Database interaction explains how a web application processes a user's request and returns the required response. It is an important concept in web development because most websites use this type of architecture.

1. Browser (Client)

The browser acts as the client. It is used by the user to access a website or web application. Examples include Google Chrome, Mozilla Firefox, and Microsoft Edge.

The browser sends a request to the server when the user performs an action such as opening a webpage, clicking a button, submitting a form, or searching for information.

2. Server

The server receives the request from the browser and processes it. It contains the application logic required to handle user requests.

The server:
- Receives HTTP requests.
- Processes the requested operation.
- Communicates with the database when required.
- Generates an appropriate response.
- Sends the response back to the browser.

Examples of server-side technologies include Node.js, Java, Python, PHP, and .NET.

3. Database

The database is used to store and manage application data. For example, a student management system may store student names, register numbers, marks, and attendance.

Common databases include MySQL, MongoDB, PostgreSQL, and Oracle.

When the server requires data, it sends a query to the database. The database processes the query and returns the required data to the server.

4. Request and Response Process

The interaction takes place in the following sequence:

User → Browser → Server → Database → Server → Browser → User

1. The user performs an action in the browser.
2. The browser creates an HTTP request.
3. The request is sent to the server.
4. The server processes the request.
5. If data is required, the server sends a query to the database.
6. The database processes the query and returns the requested data.
7. The server prepares the response.
8. The server sends the response to the browser.
9. The browser displays the result to the user.

5. Example

Suppose a student searches for their exam marks. The browser sends the request to the server. The server checks the database for the student's marks. The database returns the marks to the server, and the server sends the result back to the browser. The browser displays the marks to the student.

Flow:

Student
   ↓
Browser
   ↓ HTTP Request
Server
   ↓ Database Query
Database
   ↓ Student Marks
Server
   ↓ HTTP Response
Browser
   ↓
Student sees marks

Conclusion:

The browser–server–database model provides a clear understanding of how web applications work. The browser sends requests, the server processes the requests and manages application logic, and the database stores and retrieves information. Finally, the server sends the processed result back to the browser, which displays it to the user.

ACTIVITY 2: PROBLEM SOLVING USING FLOWCHARTS AND PSEUDOCODE
============================================================

Title:
Students solve progressively complex logical problems using flowcharts and pseudocode before implementing them in code.

Introduction:
Problem solving is an important fundamental skill in programming. It involves understanding a problem, analyzing its requirements, developing a logical solution, and converting the solution into a program. Before directly writing code, flowcharts and pseudocode are used to represent the solution clearly.

1. Problem Identification

The first step is to understand the given problem clearly. Students identify what the problem requires and determine the information needed to solve it.

A problem is generally divided into:
- Input – Data provided to the program.
- Process – Operations performed on the input.
- Output – Result produced by the program.

For example, to calculate the average of three marks:
Input: Three marks
Process: Add the marks and divide by 3
Output: Average mark

2. Algorithm Development

An algorithm is a step-by-step procedure used to solve a problem. It provides a logical sequence of instructions before implementation.

A good algorithm should be:
- Clear
- Simple
- Finite
- Correct
- Efficient
- Easy to understand

3. Pseudocode

Pseudocode is an informal representation of an algorithm using simple English and programming concepts. It does not follow the strict syntax of any particular programming language.

Example: Checking whether a number is even or odd.

START
Read number
IF number MOD 2 = 0 THEN
    Display "Even Number"
ELSE
    Display "Odd Number"
END IF
STOP

Pseudocode allows students to focus on logic rather than programming syntax.

4. Flowcharts

A flowchart is a graphical representation of an algorithm. It uses standard symbols to show the sequence of operations and decisions.

Important flowchart symbols are:
- Oval – Start / Stop
- Rectangle – Processing
- Parallelogram – Input / Output
- Diamond – Decision
- Arrow – Direction of flow

Flowcharts make the logic of a program easier to visualize.

5. Progressive Complexity

Students can solve problems in increasing levels of difficulty.

Level 1 – Basic Problems:
- Addition of two numbers
- Finding the area of a circle
- Calculating simple interest
- Converting temperature

Level 2 – Decision-Making Problems:
- Odd or even number
- Positive or negative number
- Largest of two or three numbers
- Student grade calculation

Level 3 – Looping Problems:
- Factorial of a number
- Fibonacci series
- Prime number checking
- Sum of digits
- Multiplication table

Level 4 – Advanced Problems:
- Searching algorithms
- Sorting algorithms
- Matrix operations
- Pattern generation
- Menu-driven applications

6. Converting Pseudocode into Code

After verifying the algorithm using pseudocode and flowcharts, students implement it using a programming language.

The process is:

Problem
   ↓
Understand Requirements
   ↓
Develop Algorithm
   ↓
Write Pseudocode
   ↓
Draw Flowchart
   ↓
Implement in Code
   ↓
Test and Debug
   ↓
Final Solution

7. Testing and Debugging

After implementation, the program is tested with different inputs. Students check whether the output is correct. If an error is found, the program is debugged by identifying and correcting the error.

Testing helps identify:
- Logical errors
- Syntax errors
- Incorrect calculations
- Invalid inputs
- Unexpected outputs

8. Advantages

Using flowcharts and pseudocode before coding provides several benefits:
1. Improves logical thinking.
2. Makes complex problems easier to understand.
3. Reduces programming errors.
4. Helps identify missing steps.
5. Makes algorithms easier to modify.
6. Provides a clear structure for coding.
7. Helps beginners learn programming systematically.
8. Makes communication between programmers easier.
9. Simplifies debugging and testing.
10. Encourages efficient problem-solving techniques.

9. Example: Finding the Largest of Three Numbers

Pseudocode:

START
Read A, B, C

IF A > B AND A > C THEN
    Display A is largest
ELSE IF B > A AND B > C THEN
    Display B is largest
ELSE
    Display C is largest
END IF

STOP

Flow:

START
  ↓
Read A, B, C
  ↓
Is A > B and C?
 /        \
Yes        No
 ↓          ↓
Display A   Is B > A and C?
largest      /       \
            Yes       No
             ↓         ↓
        Display B   Display C
         largest     largest
             \        /
               ↓
              STOP

Conclusion:

Solving problems using flowcharts and pseudocode before coding provides a systematic approach to programming. Students first understand the problem, develop an algorithm, represent it using pseudocode and flowcharts, and then convert it into actual code. By solving problems progressively from simple operations to advanced logical problems, students develop strong problem-solving, analytical, and programming skills.

ACTIVITY 3: IDENTIFYING FRONTEND, BACKEND, AND DATABASE COMPONENTS
============================================================

Title:
Students identify common applications they use daily and map their frontend, backend, and database components.

Introduction:
Modern applications such as WhatsApp, Instagram, YouTube, Amazon, Google Maps, and online banking applications consist of multiple components working together. The three major components of a web or mobile application are Frontend, Backend, and Database. Students can study applications they use every day and identify how these three components interact to provide different services to users.

1. Frontend

The frontend is the part of an application that users can see and interact with. It provides the user interface and accepts user inputs.

Examples of frontend elements include:
- Buttons
- Menus
- Text boxes
- Images
- Search bars
- Forms
- Product pages
- Navigation screens

Common frontend technologies include HTML, CSS, JavaScript, React, Angular, and Vue.js.

2. Backend

The backend is the server-side component of an application. It processes requests received from the frontend and performs the required operations.

The backend is responsible for:
- Processing user requests
- User authentication
- Business logic
- Data processing
- Communication with databases
- Sending responses to the frontend

Common backend technologies include Node.js, Python, Java, PHP, C#, and Express.js.

3. Database

A database is used to store and manage the information required by an application. For example, an e-commerce application may store user information, product details, prices, orders, payment information, and delivery details.

Common databases include MySQL, MongoDB, PostgreSQL, Oracle, and Microsoft SQL Server.

4. Mapping Daily Applications

Instagram:
The frontend consists of the mobile or web user interface. The backend handles user authentication, posts, comments, likes, and other application operations. The database stores user information, posts, comments, likes, and related data.

YouTube:
The frontend provides the video interface, search interface, and user controls. The backend handles video processing, recommendations, authentication, and APIs. The database stores user information, video information, comments, playlists, and other related data.

Amazon:
The frontend provides product pages, shopping cart, search, and checkout interfaces. The backend handles product management, orders, payments, authentication, and delivery operations. The database stores product details, customer information, orders, and related information.

WhatsApp:
The frontend provides the chat interface, contact list, status, and calling features. The backend handles messaging, authentication, notifications, and communication services. The database stores user-related information and other application data.

Online Banking:
The frontend provides the banking interface for checking balances, transferring money, and viewing transactions. The backend processes authentication, transactions, account operations, and other banking services. The database stores account information, customer details, transaction records, and related data.

5. Example of Online Shopping Application

Consider an online shopping application. When a user searches for a product, the user first enters the product name in the frontend. The frontend sends the request to the backend server. The backend processes the request and sends a query to the database. The database searches for matching products and returns the required information to the backend. The backend processes the result and sends it back to the frontend. Finally, the frontend displays the products to the user.

The overall process is:

USER → FRONTEND → BACKEND SERVER → DATABASE → BACKEND SERVER → FRONTEND → RESULT TO USER

6. Importance of Component Mapping

Mapping frontend, backend, and database components helps students understand how applications are structured. It explains how user actions are processed, how data is stored and retrieved, how frontend and backend communicate, how databases support applications, and how different technologies work together. It also helps students understand the basic concepts required for developing real-world applications.

7. Three-Tier Architecture

Most applications can be understood using a three-tier architecture. The first layer is the frontend or presentation layer, which provides the user interface. The second layer is the backend or application layer, which contains business logic and processes requests. The third layer is the database or data layer, which stores and manages application data.

The architecture can be represented as:

FRONTEND
User Interface (UI)
        ↓
BACKEND
Business Logic and APIs
        ↓
DATABASE
Data Storage and Query Processing

Conclusion:

Identifying frontend, backend, and database components in daily-use applications helps students understand the basic architecture of modern software systems. By mapping these components, students can clearly understand how the user interface, server-side processing, and data storage work together to provide a complete application. This knowledge provides a strong foundation for web development and full-stack application development.
