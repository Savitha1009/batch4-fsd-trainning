THREE ACTIVITIES – THEORETICAL ANSWERS

ACTIVITY 1: API DATA RETRIEVAL
============================================================

Title:
Students consume public APIs and display data dynamically on webpages.

Introduction:

An API (Application Programming Interface) is a set of rules and methods that allows different software applications to communicate with each other. APIs are commonly used in modern web applications to retrieve data from external services and display it to users.

API data retrieval helps students understand how a webpage can request information from an external server and dynamically display the received data.

1. Understanding APIs

An API acts as an interface between two applications. A webpage can send a request to an API, and the API returns data in a structured format.

A common format used for API responses is JSON (JavaScript Object Notation).

For example, an API may return:

{
    "name": "Student",
    "age": 20,
    "course": "Computer Science"
}

2. Public APIs

Public APIs provide data or services that developers can access for learning and application development. Examples include weather APIs, public news APIs, country information APIs, currency APIs, and other open data services.

Students can use suitable public APIs to retrieve information and display it on a webpage.

3. API Request and Response

The basic process is:

User Opens Webpage
        ↓
JavaScript Sends API Request
        ↓
API Server Processes Request
        ↓
API Returns Data
        ↓
JavaScript Receives Response
        ↓
Data is Processed
        ↓
Data is Displayed on Webpage

4. Fetch API

JavaScript provides the Fetch API to request data from a server.

A simple example is:

fetch("API_URL")
    .then(response => response.json())
    .then(data => {
        console.log(data);
    })
    .catch(error => {
        console.log(error);
    });

The fetch() function sends a request to the API. The response is converted into JSON and then processed using JavaScript.

5. Displaying API Data

After receiving the API response, JavaScript can dynamically display the information on the webpage.

For example, if a weather API provides temperature and weather condition data, JavaScript can display:

City: Chennai
Temperature: 30°C
Condition: Clear

6. Important Concepts

Students learn the following concepts through API data retrieval:

- HTTP requests
- API endpoints
- JSON data
- Fetch API
- Promises
- Asynchronous programming
- Error handling
- DOM manipulation
- Dynamic webpage updates

7. Error Handling

API requests may fail because of an invalid URL, network problems, server errors, or unavailable services. Therefore, applications should handle errors properly.

For example:

- Display "Unable to load data."
- Show a loading message.
- Check whether the response is successful.
- Handle invalid or missing data.

8. Example Activity

Students can create a webpage that retrieves information from a public API and displays it dynamically.

The webpage may contain:

- A heading
- A button to retrieve data
- A loading message
- A data display area
- An error message

When the user clicks the button, JavaScript sends a request to the API and displays the returned information.

9. Advantages

API data retrieval provides several benefits:

- Connects webpages with external services.
- Provides real-time or updated information.
- Reduces the need to manually enter data.
- Helps build dynamic applications.
- Demonstrates client-server communication.
- Improves programming and web development skills.

Conclusion:

API Data Retrieval helps students understand how modern websites communicate with external services. By consuming a public API and displaying the returned information dynamically, students gain practical knowledge of HTTP requests, JSON, Fetch API, asynchronous programming, error handling, and DOM manipulation.

ACTIVITY 2: TEAM COLLABORATION SIMULATION
============================================================

Title:
Students work in teams using Git branches, pull requests, and code reviews.

Introduction:

Team collaboration is an important part of software development. Multiple developers often work on the same project at the same time. Git is a distributed version control system that helps developers track changes, manage different versions of code, and collaborate effectively.

GitHub and similar platforms provide additional features such as branches, pull requests, and code reviews.

1. Git

Git is a version control system used to track changes in source code. It allows developers to save different versions of a project and return to previous versions when necessary.

Git helps teams:

- Track changes
- Work simultaneously
- Create separate branches
- Merge changes
- Recover previous versions
- Maintain project history

2. Git Repository

A repository is a storage location for a software project and its version history. It contains project files, source code, and information about changes made by developers.

Repositories can be stored locally or on platforms such as GitHub.

3. Git Branches

A branch is a separate line of development. Developers can create branches to work on different features without directly changing the main project.

For example:

main
  |
  +-- feature-login
  |
  +-- feature-navbar
  |
  +-- bug-fix

A developer can create a feature branch, make changes, and later merge the changes into the main branch.

4. Basic Collaboration Workflow

The team collaboration process can be represented as:

Create Repository
        ↓
Clone Repository
        ↓
Create New Branch
        ↓
Make Code Changes
        ↓
Commit Changes
        ↓
Push Branch
        ↓
Create Pull Request
        ↓
Code Review
        ↓
Make Required Changes
        ↓
Approve Pull Request
        ↓
Merge into Main Branch

5. Pull Request

A pull request is a request to merge changes from one branch into another branch. It allows team members to review the code before it becomes part of the main project.

A pull request normally contains:

- Description of changes
- Modified files
- Code comparison
- Review comments
- Testing information

6. Code Review

Code review is the process of examining another developer's code before it is merged into the main project.

During a code review, team members check:

- Code correctness
- Coding standards
- Readability
- Security
- Performance
- Possible bugs
- Duplicate code
- Proper naming
- Test coverage

7. Team Roles

Students can divide responsibilities among team members.

For example:

Member 1 – Frontend development
Member 2 – Backend development
Member 3 – Database or data management
Member 4 – Testing and documentation

Each member can create a separate branch for their assigned work.

8. Example

Suppose a team is developing a student management webpage.

The main branch contains the stable version of the project.

One student creates a branch called "student-form" and develops the registration form. Another student creates "student-list" and develops the student list. After completing their work, each student commits and pushes the changes. They then create pull requests for review.

Other team members review the changes and suggest improvements. After the changes are approved, the branches are merged into the main branch.

9. Benefits of Team Collaboration

Git-based collaboration provides several advantages:

- Multiple developers can work simultaneously.
- Changes can be tracked.
- Developers can work safely using branches.
- Code can be reviewed before merging.
- Conflicts can be identified and resolved.
- Project history is maintained.
- Team communication improves.
- Code quality can be improved.

Conclusion:

Team Collaboration Simulation helps students understand real-world software development practices. By using Git branches, pull requests, and code reviews, students learn how developers work together, manage source code, review changes, resolve problems, and maintain a stable project.

ACTIVITY 3: DEBUGGING CHALLENGE
============================================================

Title:
Students identify and fix intentionally introduced bugs in JavaScript.

Introduction:

Debugging is the process of identifying, analyzing, and correcting errors in a program. Bugs can cause incorrect results, program crashes, unexpected behavior, or failure to perform a required operation.

In this activity, students are given JavaScript programs containing intentionally introduced bugs. They identify the errors, determine their causes, fix them, and test the corrected program.

1. Types of JavaScript Errors

JavaScript programs can contain different types of errors.

Syntax Errors:
These occur when the code does not follow the correct JavaScript syntax.

Example:

if (x > 10 {
    console.log(x);
}

The missing closing parenthesis causes a syntax error.

Runtime Errors:
These occur while the program is running.

Example:

let user = null;
console.log(user.name);

Trying to access a property of null causes a runtime error.

Logical Errors:
The program runs without an error message but produces an incorrect result.

Example:

let a = 10;
let b = 5;
let result = a - b;

If the program is supposed to calculate addition, the logic is incorrect even though the code runs.

2. Debugging Process

The debugging process can be represented as:

Run the Program
        ↓
Observe the Problem
        ↓
Identify the Error
        ↓
Find the Cause
        ↓
Modify the Code
        ↓
Run the Program Again
        ↓
Test the Result
        ↓
Confirm the Bug is Fixed

3. Browser Developer Tools

Modern browsers provide developer tools that help identify JavaScript errors.

Important tools include:

- Console
- Sources
- Network
- Elements
- Debugger
- Breakpoints

The Console is commonly used to display error messages and debugging information.

4. Console Logging

Developers can use console.log() to understand the value of variables and program execution.

Example:

let total = price * quantity;
console.log(total);

This helps determine whether the calculated value is correct.

5. Breakpoints

A breakpoint pauses program execution at a specific line. Developers can inspect variable values and understand how the program is executing.

Breakpoints are useful for finding logical and runtime errors.

6. Common Bugs for Students

Students can be given intentionally incorrect programs containing:

- Missing brackets
- Incorrect variable names
- Wrong operators
- Incorrect conditions
- Missing event listeners
- Incorrect DOM selectors
- Invalid function calls
- Incorrect array indexes
- Form validation errors
- Incorrect calculations

7. Example Debugging Problem

Incorrect code:

let a = 10;
let b = 20;
let result = a - b;
console.log("Sum:", result);

Problem:
The program is expected to calculate the sum, but it uses the subtraction operator.

Corrected code:

let a = 10;
let b = 20;
let result = a + b;
console.log("Sum:", result);

The output is:

Sum: 30

This is an example of a logical error.

8. DOM Debugging Example

Suppose a webpage contains:

<button id="submitBtn">Submit</button>

But JavaScript uses:

document.getElementById("submitButton");

The selector does not match the actual HTML ID. As a result, the button interaction may not work correctly.

The student must identify the mismatch and correct the selector.

9. Debugging Strategies

Students can use the following strategies:

- Read error messages carefully.
- Check the line number mentioned in the console.
- Use console.log() to inspect values.
- Check variable names.
- Check conditions and operators.
- Verify DOM element IDs and classes.
- Test one section of code at a time.
- Use browser developer tools.
- Test the corrected program with multiple inputs.

10. Testing After Debugging

After fixing a bug, students should test the program again. They should verify that the original problem has been solved and that the correction has not introduced another problem.

Testing should include:

- Normal input
- Invalid input
- Empty input
- Boundary values
- Multiple test cases
- Different user actions

11. Benefits of Debugging Practice

Debugging activities help students:

- Develop logical thinking.
- Understand JavaScript errors.
- Improve problem-solving skills.
- Learn to read error messages.
- Understand program execution.
- Become familiar with browser developer tools.
- Improve code quality.
- Develop systematic testing habits.

Conclusion:

The Debugging Challenge helps students develop the ability to identify and correct JavaScript errors. By working with intentionally introduced bugs, students learn how to analyze syntax, runtime, and logical errors, use developer tools, test their solutions, and develop systematic debugging techniques.


============================================================
OVERALL LEARNING OUTCOME
============================================================

After completing these three activities, students will understand important practical concepts of modern web development. They will learn how to retrieve and display data from APIs, collaborate with other developers using Git, branches, pull requests, and code reviews, and identify and fix JavaScript bugs using systematic debugging techniques.

These activities improve students' knowledge of API communication, asynchronous JavaScript, version control, teamwork, code review, debugging, testing, and problem solving. Together, they provide practical skills required for developing and maintaining modern web applications.
